# 0005 · 鉴权接入：kit net/http 适配 + 本仓策略表

- **状态**：已裁决（来源：裁-15，2026-10-25）
- **场景**：`internal/httpapi` 的鉴权闸此前只有接口（`Authorizer`），没有实现，线上 monitor/* 恒 503；审计 `actor` 恒为空串；`Store.ListAudit` 只有进程内接口，没有对外读取面。kit `v0.1.1` 已提供 `auth/httpadapter`（`Authenticate` / `Authorize` / `DecideStartup` / `Policy`），机制不再需要各服务各写一份。
- **决策**：
  1. **机制在 kit、策略在本仓**：`internal/httpapi/auth.go` 实现 `Authorizer`，内部调 `httpadapter.Authenticate`（Bearer → `Parse` → 拒 `kind != access` → 校验 subject）与 `httpadapter.Authorize`（Public / AnyAuthenticated / Roles，角色 any-of）；`internal/httpapi/policy.go` 保存本仓唯一的「路由 → 角色」表。
  2. **所有端点过闸，fail-closed**：`New` 从同一份路由表注册并逐个包 `requireAuth`；`Authorizer` 未装配 → `503 auth_unavailable`，无凭证 → 401，越权 → 403。不再有「monitor/* 才受保护」的分裂面。
  3. **角色口径**：读端点 `viewer`；写端点 `trader`；规则审批 `admin`。`resolve`（latest 会落快照）与事件 / 熔断按写口径 `trader`；`monitor/evaluate` 只读不写库，按读口径 `viewer`。
     **补裁（2026-10-25，裁-17）**：服务间角色 `service` 只开 `resolve` / `events` 两条，`audit` 与规则管理面不开 —— 口径与作用域见 [0006](0006-service角色只开两条服务间链路.md)；本条其余部分不变。
  4. **审计 actor 取自 claims**：`create` / `update` / `approve` 从鉴权上下文取 `username`（缺失退 `subject`），不由请求体自报；显式 open-access（无 secret + 回环）记常量 `open-access`，**永不写空串**。
  5. **审计读端点**：新增 `GET /api/risk/audit?rule_id=`（viewer），形状 `{audit:[],count}`，空列表编码 `[]`。
  6. **启动闸**：复用 `httpadapter.DecideStartup`——有 secret 开鉴权；无 secret + 回环 = 开放；无 secret + 非回环 = **拒绝启动**（容器须显式 `AUTH_INSECURE_EXPOSURE=loopback-published`）。
- **理由**：token 校验、refresh/access 区分、角色 any-of 与启动闸都是跨服务同一套语义，留在 kit 才不会漂移；「哪个端点要哪个角色」是本仓业务，留在本仓才可审计。策略表与路由表同源注册，守卫测试双向对拍，漏登即红。
- **代价 / 后果**：
  - 新增对 `github.com/ruoxizhnya/tellurion-kit v0.1.1` 的依赖（其编译闭包含 gin，但本仓源码不 import gin）。
  - 鉴权开启后，core 侧调用 `resolve` / `events` / `breakers` 必须持有效 access token（角色 `trader` 及以上）；token 分发属 core 侧接线，不在本仓。
  - open-access 只允许回环绑定；非回环未配 secret 的进程直接起不来，这是有意的失败方向。
- **替代关系**：不替代 0001–0004；ADR-0004 的「monitor 三端点强制鉴权闸」由本条扩展到全部端点。
