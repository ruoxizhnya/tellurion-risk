# 0001 · 两层结构：真相源出仓、裁决留内核

- **状态**：已裁决（来源：ADR-D20 / risk-service-design.md §1、§5）
- **场景**：风控有两条完全不同的时间尺度：规则的定义与审批是"周级、人参与"；每笔订单的裁决是"微秒级、机器"。把两者做成一个服务，结果是热路径被网络 RTT 绑死，或者为了性能把规则硬编码回内核（等于没服务化）。
- **决策**：两层：① 服务侧持规则真相源 + 版本 + 快照 + 聚合监控 + 熔断；② 内核进程内持 `RiskPolicy`，按快照构建，每笔同步裁决，**零网络**。
- **理由**："要不要放行这一单"必须在微秒级回答；"这套规则该不该生效"可以等一次审批。按时间尺度切，边界才稳定，也不必为了性能做妥协。
- **代价 / 后果**：① 两层之间有一致性窗口（规则改了，跑着的 run 仍用旧快照 —— 这是**有意**的，保证可复现）；② 事件回传是异步的，监控有延迟；③ 内核侧要维护 `RiskPolicy` 的构建与缓存。
- **替代关系**：无（本仓首条）
