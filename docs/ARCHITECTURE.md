# 本仓边界与依赖方向 — tellurion-risk

## 定位

风控规则的**真相源**：规则定义、限额表、聚合监控与熔断。**同步裁决（`RiskPolicy`）留在 core 进程内**。

状态：**预留（S0 占位，触发式启动）——尚未启动，无实现**

## 依赖方向（编译器强制）

```
contracts + kit
        ↑
  tellurion-risk  ──(限额快照/事件)──▶  core（进程内裁决）
```

- 箭头 = import 方向。**不允许反向**，也不允许成环 —— 反向 import 应当**编译失败**，这是判据不是口号。
- 跨仓只认版本号：`tellurion-risk` 以需要的版本出现在下游 `go.mod`。

## 边界表

| | 内容 |
|---|---|
| 允许 | 持有 `risk` schema 的 DDL 与规则版本；下发限额快照给 core 的进程内裁决层；聚合监控与熔断（跨 run 维度） |
| 禁止 | 把逐笔 / 逐 bar 裁决做成远程调用（硬否决）；import core 的实现包；持有订单/持仓真相（那是 core） |

## 关键约束

1. **单仓可构建**：`go build ./...` / `go vet ./...` / `go test ./...` 不依赖任何兄弟目录。
2. **无 `replace`**：指向仓外的 `replace` 一律不接受（CI 会查）。
3. **无 `go.work` 入库**：本地联调可以建，提交即错。
4. **两层结构**：服务做真相源 + 聚合监控；进程内做每笔/每 bar 的同步裁决。只有前者能出仓。
